The Problem

The industry is discovering something uncomfortable.

The Exhaustion Problem

Four parallel agents and you're wiped out by mid-morning. Every inch of experience goes into prompting, reviewing, course-correcting. The productivity-leisure narrative was wrong — the frontier is harder, not easier. The bottleneck moved from generating code to managing the things that generate code.

The Trust Problem

97% filter effectiveness on prompt injection is a failing grade. Permission prompts you click through out of fatigue. Sandboxes that aren't real containers. The security model for one careful agent doesn't survive contact with ten autonomous ones. Architectural isolation or nothing.

The Memory Problem

Tests and documentation used to mean good software. Now an agent generates both in an hour. The new trust signal is whether a human curated the knowledge — whether someone actually decided what the system should remember, and what it should forget.

The hype answer: remove the human. Fully autonomous agents, AI "companies" where every role is an LLM instance. But the game of telephone between agent layers causes regression to the mean. Memory degrades without consolidation. Context drifts without correction. Feeling productive and being productive are two very different things.

multiplai takes the opposite bet: the tighter the human feedback loop, the faster the system improves. Not an orchestrator — a harness. The agent is already good enough. The human's tooling isn't.

The Design

Five pillars of an AI system that actually works.

These aren't features. They're necessary conditions. Remove any one and the system degrades.

01 · Memory

Transparent, file-based, human-curated.

No vectors, no embeddings. Human-readable markdown files organised by topic. Intent-based retrieval ("what would help this task?") instead of similarity matching. Four corpora: identity, knowledge, work, standards. Nothing enters long-term memory without human review. You can open any memory file, read it, edit it.

02 · Deep Research

Not search. Research.

An 8-stage pipeline with divergence, fact-checking, and contrarian steps. Search fallback chain across providers. 127 tests. Not the shallow kind where you fan out queries — real research that challenges its own findings before presenting them.

03 · Isolation

Every agent in its own container.

Docker containers with no privileges, capability drops, socket-only access. The container is the blast radius boundary. You trust freely because the worst case is bounded. Sub-second container starts via OrbStack. No permission fatigue, no YOLO on your desktop.

04 · Coordination

Code orchestrates. LLMs reason.

Deterministic workflows in Python, not prompts. Skills evolve: fat prompt → script → Agent SDK call. Zero orchestrator tokens. The multi-agent 15x token cost comes from LLM-powered orchestrators. Background agents run cron-based jobs: nightly consolidation, weekly memory audits, transcript mining.

05 · Human-in-the-Loop

The easier the feedback, the faster the system compounds.

Tinder-style triage for learnings: approve, reject, edit. Each one slides out in 150ms. Twelve learnings triaged in 90 seconds. The system captures insights every session. The human decides which ones stick. That's the quality gate that makes everything else work.

Batteries Included

Not just a UI. A full system.

The app is how you steer it. This is what you're steering. Each piece works independently. Together, they create a system that remembers, learns, reviews its own work, and gets better every session.

Memory System

4 corpora: identity, knowledge, work, standards. Intent-based retrieval per prompt. Human-curated. Every agent starts with the right context.

Context Handoff

Monitors token usage via StreamEvent. Checkpoints at 70% fill, kills the context, restarts clean. No compaction degradation after 3+ cycles.

Code Orchestrator

Deterministic Python workflows. Skills evolve: fat prompt → script → Agent SDK call. Zero orchestrator tokens. LLMs handle reasoning. Code handles everything else.

Deep Research

8-stage pipeline: plan, diverge, challenge, search, triage, read, reassess, synthesise. 127 tests. Search fallback chain across providers. Production-grade.

Morning Digest

Synthesised activity summary. What completed, what's stuck, what needs a decision. Cached and ready when you open the app.

Session Forking

Clone a session's context into a new session. Explore a branch without losing the trunk. One click to fork, full context carried over.

Context Proposal

Tell the system what you want to do. It proposes relevant files, memory, and past sessions. Intelligent context negotiation before work begins.

Learnings Capture

Every session produces insights. Auto-extracted from transcripts, tagged with trust levels (verified, high, medium). Queued for human triage.

Hooks & Lifecycle

15 hooks: session diary, memory retrieval, auto-commit, syntax validation, model resolution, venv guard. The nervous system that connects everything.

Eval Suite

3-tier test suite: unit tests (free), eval tests (LLM-judged), integration tests. Routing accuracy, skill triggers, commit messages, learnings quality.

The Kit

You don't need the app. The foundation ships standalone.

The skills, hooks, memory system, container setup, and eval suite are a separately distributable kit. Clone it, run setup, and launch Claude Code with the full system. No native app required. This is where most of the value lives.

Questions

Common questions.

Does this only work with Claude?

Yes, by design. multiplai is built on the Claude Agent SDK. Hooks, skills, and memory are deeply integrated in ways that don't port to other models. But the gateway architecture is agent-runtime agnostic — the container can run anything that speaks WebSocket. Claude is the current bet, not a permanent lock.

Is this free?

Open source under MIT licence. You bring your own Anthropic API key. No subscription, no middleman, no token markup.

Do I need Docker?

Yes. Each agent runs in an isolated Docker container. On macOS, OrbStack is recommended for sub-second container starts. Docker Desktop works too. The kit also supports a --local mode that runs without containers if you prefer.

How is this different from multiple terminal sessions?

Six tmux panes and you can't tell which one needs attention. multiplai shows every agent with a status dot and a one-line summary. Green: done. Amber: needs your decision. Purple: running. Plus a morning digest, cross-session artifact browsing, and a learnings pipeline that makes the system smarter every session. Terminals can't do any of that.

What's the difference between multiplai and the kit?

The kit is the foundation: 35 skills, 15 hooks, memory system, container setup, eval suite. It works with Claude Code in a terminal — no native app needed. multiplai adds the native Mac app, the gateway, WebSocket connectivity, and the Feed/Triage/Focus UI. The kit gives you 80% of the value. The app gives you control at scale.

Is the iOS app available?

Not yet. The Mac app is shipping. The iOS app uses the same SwiftUI codebase and connects to the same gateway — it's the next piece being built. The architecture is ready; the app is coming.

Is the memory system a vector database?

No vectors, no embeddings. Human-readable markdown files organised by topic. Intent-based retrieval ("what would help this task?") instead of similarity matching. You can open any memory file, read it, edit it. Nothing enters long-term memory without your review.
